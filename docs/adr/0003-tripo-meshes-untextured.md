# Tripo meshes become palette-coloured sections, never textures

When the Team wants a more detailed 3D model, we generate it with Tripo (`tools/tripo_model.py`: `smart_low_poly`, painted, no PBR) and immediately bake the paint away: each triangle is sampled, snapped to the Style Lock palette, and the mesh is saved as one section per palette colour with no textures or UVs. In-game, `src/models.js` shades the sections with the same flat Lambert colours as the hand-built primitives. Shipped textures would clash with the toy look of everything else and bloat GitHub Pages; Tripo's own `generate_parts` was the alternative for separable parts, but it can't be combined with `smart_low_poly`. The painted original is kept git-ignored in `assets/models/_source/` so sections can be re-baked with a new palette without paying again. The API key lives in the `TRIPO_API_KEY` environment variable on the session machine, never in the repo.
